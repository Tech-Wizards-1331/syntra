<objective>
Implement full CRUD capabilities for Hackathons, Problem Statements, and Scan Categories in the Organizer panel. Utilize direct signed Cloudinary uploads for PDF attachments, implement concurrency-safe transaction ordering, apply strict status transition gates, enforce authorization boundaries, and wrap the features in glassmorphic Next.js pages.
</objective>

<threat_model>
### Trust Boundaries
- **Server Action Authorization**: Validate that the requesting user's session corresponds to an organizer role and is the owner of the target hackathon/profile.
- **Direct Upload Verification**: Ensure that PDF attachment URLs saved to the database originate from the authorized Cloudinary folder and validate PDF magic bytes client-side before upload.

### STRIDE Register
| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Information Disclosure | Hackathon Server Actions | mitigate | Check session user ID / organizer ID ownership on all read/write actions. |
| T-05-02 | Tampering | Cloudinary Uploads | mitigate | Use server-generated signed upload parameters restricting directory and timestamps; run client-side magic-byte validations. |
| T-05-03 | Elevation of Privilege | Scan Categories / Actions | mitigate | Block access to edit/delete operations unless session is verified as the owning organizer. |
</threat_model>
